# 完全本地的 5 小时额度接入方案

日期：2026-10-21。根据用户要求修订：鳄鱼工具本身不联网，不调用在线额度接口，不启动额度查询 app-server，不提取登录凭据。本文保留方案背景，已实现行为及显示规则以 CROC_README.md 为准。

## 数据边界

本机近期 Codex JSONL 日志已确认包含 rate_limits.primary.used_percent、window_minutes=300、resets_at。工具只观察 Codex 客户端已写到本机的记录。Codex 自己进行在线任务，不等于鳄鱼工具需要联网。

这是最后一次写入的真实额度快照，不是离线实时查询服务器：其他设备或云端消耗、账号切换、服务端重置只有在新本地记录出现后才能确认。日志多久产生新额度不受本工具控制。不承诺服务器变化到界面显示的端到端延迟。

## 纯本地数据链路

Codex 本地日志 → 增量额度解析 → 内存中的账号额度快照 → C# 透明窗口。

不依赖网页、浏览器控制、HTTP、本机 Web 服务或网络请求。额度从日志直接取值，不使用消息长度或 Token 总量推算。

## 低延迟策略

1. 启动时只读取近期活跃日志的尾部，找到最近的有效额度记录；如未找到，按需向前读取有限数据，不在动画线程扫描完整历史。
2. 复用现有增量日志读取：记录文件偏移，只读新追加字节，处理半行、文件截断和轮换。
3. Windows 文件变更通知用于唤醒后台读取；保留 100–200 毫秒轮询兜底。通知是提示，不等于完整写入；半行等下次再解析。
4. 新有效额度立即更新内存并通知 UI；C# 在下一动画帧刷新。目标是完整额度记录落盘后约 100–300 毫秒内显示，需实测验证，不作为已实现保证。
5. 跨进程优先使用本地命名管道发送小型派生数据；第一版可复用 runtime JSON 文件，原子写入，C# 每 100 毫秒检查变更。不要每个动画帧重读所有日志。
6. 额度监测账号近期活动日志，不只盯用户选中的单个对话；动画速率仍来自选中对话。只提取额度、窗口、重置时间和记录时间，不另存聊天正文。

## 解析规则

选择 limit_id=codex 的 300 分钟窗口；不把 primary 永久认作 5 小时，不混合其他模型桶或 10080 分钟周额度。取记录时间最新的有效快照，拒绝过期或乱序覆盖。

remaining_percent=clamp(100-used_percent,0,100)。缺字段、无额度记录、无相应窗口时显示未知，不把缺失当 0% / 100%。

日志备用字段：quota.status（recorded/unknown/awaiting_reset）、remaining_percent、used_percent、window_minutes、resets_at、recorded_at、source=local_log、limit_id。永久注明日志记录来源，右键显示最近记录时间。账号身份无法确认时不声称该快照已匹配当前登录账号；识别到切换后清空快照等待新记录。

到达 resets_at 后标记“等待新额度记录”，不自行补满奶瓶。没有新日志时保留带时间说明的旧快照；过重置时刻的数值不再表现为当前可用余额。

## 视觉建议

五个奶瓶、每瓶 20% 容量，液面表达剩余额度。休息时也保留。无数据或等待重置记录时有明确未知状态。右键显示精确百分比、重置时间、记录时间和“本地日志快照”。

便便固定从屁股处输出一行，移动速度表示最近完成响应的平均输出 tok/s。速度和额度分别来自对话层、账号层。

## 验收

- 通过观察工具进程验证没有发起网络连接；不是要求 Codex 客户端断网。
- 用可控 JSONL 追加记录测量“完整写入 → 解析 → 窗口刷新”的中位数及 P95 延迟。
- 测试半行、文件轮换、通知丢失、多个活跃日志乱序、空值、0/100%、跨重置时刻、账户切换和长时间无新记录。
- 确认不在本地推算远端新额度，不把日志年龄隐藏。
